# Engine 性能基线（EN-001）

本文记录 EN-001 的可重复测量入口、本机基线及优化验收门槛。这些数值只用于同类本机环境的回归筛查，不是跨设备或公网性能承诺；任务状态以 [todolist](./todolist.md) 为准。

## 运行方式

在仓库根目录执行：

```bash
dotnet restore Aeterni.Tunnel.Engine.Benchmarks/Aeterni.Tunnel.Engine.Benchmarks.csproj
dotnet run --project Aeterni.Tunnel.Engine.Benchmarks/Aeterni.Tunnel.Engine.Benchmarks.csproj -c Release --no-restore
```

快速冒烟使用 `--quick`，会减少通道、控制帧和传输样本，并省略 8 连接档位；它不能用于门槛判定：

```bash
dotnet run --project Aeterni.Tunnel.Engine.Benchmarks/Aeterni.Tunnel.Engine.Benchmarks.csproj -c Release --no-restore -- --quick
```

程序输出为逗号分隔的 `key=value` 行，便于其他 Agent 保存或转换为表格。TCP/TLS 测量绑定回环地址并使用自签名证书；客户端仅在基准程序中关闭证书信任校验，TLS 协议仍启用 TLS 1.2/1.3。这个例外不能复制到生产配置。

## 环境与负载

- 运行日期：2026-09-22（Asia/Shanghai）。
- 系统：macOS 27.0.0，Darwin，Arm64，8 个逻辑处理器。
- SDK：.NET SDK 10.0.300（global.json 允许 10.0.100 的 latestFeature）；运行时 .NET 10.0.8。
- 构建：Release；Server GC 为 false；无外部 BenchmarkDotNet 依赖。
- 预热：各场景 3 次。帧编解码重复 5 轮；控制帧 500 个样本；ChannelMultiplexer 发送 5,000 个 1 KiB 消息；慢消费者暂停读取 50 ms，写入 128 个 64 KiB 消息并排空；单连接传输发送 500 个 4 KiB 回显消息；并发传输使用 1/4/8 条连接，每条发送 250 个 1 KiB 回显消息。
- CPU 和内存：从第一项帧测试开始到全部场景结束，每 10 ms 采样一次进程工作集和托管堆；CPU 为进程总 CPU 时间，百分比以单个逻辑核为 100%，可超过 100%；峰值是采样最大值，不保证捕获不足 10 ms 的尖峰。包含基准本身的证书生成和采样开销，不是单个 Engine 操作的开销。
- 重复：新增监测后的完整命令连续执行 3 次；首次阶段的两次结果另列，因监测负载不同不可直接作 A/B 对比。系统负载、CPU 调频、套接字缓冲和本机安全策略会影响结果。

## 冻结的回归门槛

绝对筛查仅适用于上述 macOS Arm64 / .NET 10 Release 环境；这些值刻意低于三次观测的最低正常值，负责发现数量级退化，不作为发布 SLA：

| 指标 | 本机最低要求或最高上限 |
|---|---:|
| FrameCodec 64 B / 1 KiB / 64 KiB 吞吐 | ≥ 1,500,000 / 1,200,000 / 55,000 ops/s |
| FrameCodec 64 B / 1 KiB / 64 KiB 分配 | ≤ 450 / 2,750 / 157,600 B/op |
| ChannelMultiplexer 1 KiB 吞吐 | ≥ 150 MiB/s |
| 单连接 TCP+TLS 4 KiB 吞吐 | ≥ 30 MiB/s |
| 8 连接 TCP+TLS 1 KiB 总吞吐 | ≥ 25 MiB/s |
| TCP+TLS 控制帧 p50 / p95 / p99 | ≤ 120 / 300 / 650 µs |
| 单连接 / 8 连接 TCP+TLS 建连 | ≤ 100 / 350 ms |
| 总进程 CPU 时间；峰值工作集；峰值托管堆 | ≤ 3,500 ms；≤ 128 MiB；≤ 64 MiB |
| 慢消费者写入在暂停读取时完成 | 必须为 false，随后必须排空全部 128 个消息 |

相对门槛在 EN-031 和此后优化时适用：在同一台机器、同一 SDK、Release 配置、完全相同的协议/TLS 与证书信任模式下，对基线提交与候选提交各运行至少 5 次完整命令，交错运行以抵消设备温度和后台负载。比较各指标的中位数：吞吐不得低于基线的 80%；分配不得超过 110%；CPU 时间不得超过 120%；峰值工作集/托管堆、控制帧 p50 不得超过 125%；控制帧 p95/p99 不得超过 150%；TLS 建连不得超过 130%。慢消费者必须完成上述逻辑检查。任一绝对筛查失败或相对中位数越界，先重复同负载测量；若任一组吞吐或延迟的 `(最大值 - 最小值) / 中位数 > 30%`，该组记为**不稳定**，不能宣称通过或回退，应控制后台负载后重新测量。当前三次 TCP 吞吐与尾延迟已出现较大波动，不能把单次峰值作为目标。

## 覆盖范围与后续验证

当前入口覆盖 EN-001 所需的小包、大流、慢消费者和多连接档位。控制帧测的是 FrameCodec 回显往返，并非 ATS 登录/业务处理时间；CPU 和内存是整轮进程总值，不能归因到某个模块。所有传输在同机回环，跨平台、真实 NAT 和公网延迟应在 EN-050 独立测量。后续 EN-031 使用同版基准工具交错比较原版和候选实现，并保存每轮原始输出。
