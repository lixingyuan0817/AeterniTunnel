AeterniTunnel · 接入模式逻辑图

三种模式：端口映射（每隧道一个端口）｜vhost 域名反代（共享 80/443）｜Web 管理台（当前 vs 遗留）。悬停节点高亮数据流。

模式一 端口映射（allowPorts）— 任意 TCP，IP:端口 直连

ATS 在 bindPort（17070） 上与客户端保持一条控制+数据通道。客户端注册隧道时从 allowPorts 范围内申请一个公网端口，ATS 在该端口上监听并把流量经通道转发到内网。每隧道占用 1 个公网端口。留空 = 不限范围。

模式二 vhost 域名反代（vhostHttpPort / vhostHttpsPort + subDomainHost）— 域名访问

ATS 在 80 / 443 上监听 一个 入口，按 HTTP Host 头（或 TLS SNI）把请求路由到对应隧道。客户端注册隧道时带 Subdomain，若配置了 subDomainHost（如 aeterni.dev）则域名为 {subdomain}.aeterni.dev。一个端口承载无限多个服务，前提是 DNS 把 *.aeterni.dev 解析到服务器。

模式三 Web 管理台 — 当前 vs 遗留

当前管理走 Blazor Web 管理台（localhost:5280）：登录 webToken 后查看客户端树、隧道、日志，并可在设置页改 ATS 配置后重启生效。配置里的 webBind（127.0.0.1:7500） 是 Engine 遗留字段，没有任何代码消费它，可忽略；dashboardPort（/api/status）默认不启用，等将来开放 API 再开。
